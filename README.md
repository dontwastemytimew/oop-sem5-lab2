# Періодичні видання

Консольний застосунок на Java для лабораторної роботи №2 з ООП (варіант 11).

## Завдання

1. Створити XML-файл та відповідну йому XSD-схему. При розробці схеми використати прості та комплексні типи, переліки, граничні значення, обов'язкові атрибути та тип `ID`.
2. Створити Java-клас, що відповідає цьому опису.
3. Створити Java-застосунок для розбору XML-документа та ініціалізації колекції об'єктів інформацією з XML-файлу. Для розбору використати парсери SAX, DOM та StAX. Для сортування об'єктів використати інтерфейс `Comparator`.
4. Здійснити валідацію XML-документа з використанням XSD.
5. За допомогою XSL перетворити XML-файл у формат XML зі зміненою структурою, при якій початковий список елементів розбивається на підсписки за деякою характеристикою (у цій роботі за типом видання).
6. Уникати дублювання коду.
7. Весь код повинен бути покритий unit-тестами.
8. Код повинен бути розміщений на віддаленому репозиторії; історія змін повинна мати логічні commit-повідомлення, репозиторій має мати правильно налаштований `.gitignore`.
9. Для виведення повідомлень під час роботи програми використати засоби логування за допомогою правильно налаштованого Logger.

### Варіант 11. Періодичні видання

Кожне видання має такі характеристики:

* **Title** — назва видання
* **Type** — тип видання (газета, журнал, буклет)
* **Monthly** — щомісячне або ні
* **Chars** — характеристики:
    * кольорове (так або ні)
    * обсяг (n сторінок)
    * глянцеве (так [тільки для журналів і буклетів] або ні [для газет])
    * має підписний індекс (тільки для газет і журналів)

* Java 21
* Maven
* Log4j2
* JUnit 5

## Структура проєкту

```
src/main/java/com/periodicals
├── Main.java                  точка входу
├── model                      видання (Paper, PaperChars, PaperType)
├── parser                     PaperParser та реалізації SAX, DOM, StAX
├── service                    сортування видань
└── xml                        валідація за XSD та XSL-перетворення

src/test/java/com/periodicals  unit-тести, що віддзеркалюють структуру main

src/main/resources
├── xml
│   ├── papers.xml             вхідні дані
│   ├── papers.xsd             схема для валідації
│   └── papers.xsl             групування видань за типом
└── log4j2.xml                 налаштування логера
```

## Формат XML

Кореневий елемент `Papers` містить один або більше елементів `Paper`:

```xml
<Paper id="p2">
    <Title>Український тиждень</Title>
    <Type>magazine</Type>
    <Monthly>false</Monthly>
    <Chars>
        <Colored>true</Colored>
        <PageCount>64</PageCount>
        <Glossy>true</Glossy>
        <SubscriptionIndex>23415</SubscriptionIndex>
    </Chars>
</Paper>
```

* `id` — обов'язковий атрибут типу `ID`
* `Type` — `newspaper`, `magazine` або `booklet`
* `PageCount` — ціле число від 1 до 1000
* `SubscriptionIndex` — необов'язковий, рівно 5 цифр
* `Glossy` — необов'язковий

Результат XSL-перетворення записується у `output/papers-by-type.xml`, повідомлення програми — у консоль і файл `logs/app.log`.

## Запуск

```

```

Або запустити клас `Main` безпосередньо з IntelliJ IDEA.
